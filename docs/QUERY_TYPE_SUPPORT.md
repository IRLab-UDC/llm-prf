# Query Type Support - Multi-Query Systems

## Overview

The prf-llm framework now treats different query formulations as **separate systems** for evaluation and comparison. This means that experiments using "title only" queries and "title plus narrative" queries are analyzed independently, allowing for fair comparisons within each query type.

## Motivation

Different query formulations can significantly impact retrieval effectiveness:
- **Title Only**: Short, keyword-based queries
- **Title Plus Narrative**: Longer queries with more context
- **Title Plus Description**: Alternative longer query formulation

Treating these as separate systems allows us to:
1. Compare strategies fairly within the same query type
2. Analyze which strategies work best for different query lengths
3. Understand the interaction between query formulation and relevance feedback

## File Naming Convention

### Run Files

Run files generated by `TRECSearcherLucene` include the query type in the filename:

```
LMDirichlet-2000_title_only_...
LMDirichlet-2000_title_plus_narrative_...
LMDirichlet-2000_title_plus_description_...
```

### Summary Files

The analysis script `analyze_grid_results.sh` generates separate summary files for each strategy+query_type combination:

**Baseline:**
```
summary_baseline_title-only.tsv
summary_baseline_title-plus-narrative.tsv
summary_baseline_title-plus-description.tsv
```

**Reranker:**
```

summary_monot5_rerank_title-plus-narrative.tsv
summary_monot5_rerank_title-plus-description.tsv
```

**PRF Strategies:**
```

summary_prf_vllm_title-plus-narrative.tsv
summary_prf_vllm_prob_title-only.tsv
summary_prf_vllm_prob_title-plus-narrative.tsv
...
```

## Analysis Scripts

### analyze_grid_results.sh

The analysis script automatically:
1. Detects all unique combinations of (strategy, query_type) from run files
2. Creates separate summary TSV files for each combination
3. Reports best configurations grouped by query type

**Example output:**
```
Detected strategy+query combinations:
  - VLLM::title_only
  - VLLM::title_plus_narrative
  - VLLM-PROB::title_only
  - VLLM-PROB::title_plus_narrative
```

### visualize_grid_results.py

The visualization script:
1. Automatically discovers all summary files with query types
2. Generates comparison plots showing each strategy+query as a separate bar
3. Compares each system to the baseline **with the same query type**

**Key behaviors:**
- VLLM (Title Only) is compared to Baseline (Title Only)
- VLLM (Title Plus Narrative) is compared to Baseline (Title Plus Narrative)
- Each appears as a distinct system in comparison plots

### generate_report.py

The report generator:
1. Creates separate performance tables for each query type
2. Shows side-by-side comparisons of strategies within each query type
3. Calculates improvements relative to the corresponding baseline

## Running Experiments

### Grid Search with Multiple Query Types

To run experiments with multiple query types, simply execute multiple runs with different `searchBy` parameters:

```bash
# Title only
java -jar prf-llm.jar \
  -index /path/to/index \
  -topics /path/to/topics \
  -searchBy title_only \
  ...

# Title plus narrative
java -jar prf-llm.jar \
  -index /path/to/index \
  -topics /path/to/topics \
  -searchBy title_plus_narrative \
  ...
```

The `run_grid_search.sh` script can be modified to iterate over query types if desired.

### Analysis

After running experiments, simply execute:

```bash
./analyze_grid_results.sh robust04
```

The script will automatically:
1. Detect all query types present in the run files
2. Create appropriate summary files
3. Generate comparisons grouped by query type

## Backward Compatibility

The system maintains backward compatibility with legacy runs that don't include query type:

- Files without query type suffix are detected and handled separately
- Reports include a "Legacy (No Query Type)" section if such files exist
- No breaking changes to existing data or scripts

## Benefits

1. **Fair Comparisons**: Each strategy is compared to the appropriate baseline
2. **Query Analysis**: Understand which strategies work best for different query formulations
3. **Clarity**: Clear labeling prevents confusion about what's being compared
4. **Flexibility**: Easy to add new query types in the future
